title: Choosing a route
description: Every way to call Akashi through the Pocket portal, and which one fits your agent.
---

All routes reach the same place: the Pocket Agentic Portal, which quotes a price, takes the payment and forwards the
request to Akashi. Pick the route that matches how your agent is built.

| Route | Best for | Pays with |
|---|---|---|
| [x402 in TypeScript](/docs/calling/x402-typescript) | agents and backends in Node.js | USDC on Base (x402) |
| [x402 in Python](/docs/calling/x402-python) | Python agents | USDC on Base (x402) |
| [curl and the mppx CLI](/docs/calling/curl-and-mppx) | trying a call from a terminal | x402 or MPP (Tempo USDC.e) |
| [MCP](/docs/calling/mcp) | Claude Code, Claude Desktop, Cursor | USDC through the portal's MCP tools |

## Addresses

| | Test portal | Main portal |
|---|---|---|
| Base URL | `https://test.agent.pocket.network` | `https://agent.pocket.network` |
| x402 network | Base Sepolia `eip155:84532` | Base `eip155:8453` |
| USDC | `0x036CbD53842c5426634e7929541eC2318f3dCF7e` | `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` |
| Price | 5000 units = $0.005 | 5000 units = $0.005 |

A request URL is the portal, `/v1/`, the service ID, then the service's own path:

```text title="URL shape"
https://test.agent.pocket.network/v1/citation-verify/v1/verify
https://test.agent.pocket.network/v1/code-reality-check/v1/check
https://test.agent.pocket.network/v1/live-facts/v1/fx
```

<Callout type="warn" title="Listing status">
Akashi is registered on Pocket Network and waiting to be listed on the portal; until then these URLs answer `404`.
</Callout>

## What comes back

A paid call returns the portal's wrapper around Akashi's answer:

```json title="Shape"
{
  "portal": { "provenance": "third-party-supplier", "serviceId": "citation-verify", "schemaCheck": "passed" },
  "data": { "service": "citation-verify", "status": "complete", "results": [], "sources": [] }
}
```

`data` is always Akashi's [response envelope](/docs/contract/response). The payment receipt arrives in the
`PAYMENT-RESPONSE` header (x402) or `Payment-Receipt` (MPP). No receipt means no settled payment: do not assume one.
The portal's own errors, such as a rejected payment, use the same error shape as Akashi:
`{"error": {"code": "PAYMENT_INVALID", "message": "...", "retryable": false}}`.
