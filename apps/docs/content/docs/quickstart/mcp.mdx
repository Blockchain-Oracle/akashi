Akashi exposes the same three tools in two standard MCP ways:

| Connection | How the client connects | Who pays for a run |
| --- | --- | --- |
| Hosted | Streamable HTTP at `https://api.useakashi.xyz/mcp` | Akashi's capped demo credit |
| Local | Starts `akashi mcp` or `npx -y akashi mcp` over stdio | Your Base Sepolia test wallet, within your spend caps |

## Hosted MCP: connect by URL

No npm install or wallet is needed. Add `https://api.useakashi.xyz/mcp` as a Streamable HTTP server in your MCP client. For example:

```bash
codex mcp add akashi --url https://api.useakashi.xyz/mcp
claude mcp add --transport http akashi https://api.useakashi.xyz/mcp
```

`akashi_discover` and `akashi_inspect` are free. `akashi_run` uses limited demo credit; when the allowance is used up, use the local server with your own test wallet.

## Local MCP: run the npm CLI

The CLI runs an MCP server on your machine over stdio. It signs test USDC payments locally and sends only signed payments to the gateway. Node.js 20 or later is required.

### 1. Install the CLI

```bash
npm install -g akashi
akashi --version
```

The examples below use `npx -y akashi mcp`, which also works without a global install. If you installed globally, you may launch `akashi mcp` instead.

To enable paid runs, provide `AKASHI_PRIVATE_KEY` to the local MCP process through your client's environment or secret settings. Use a Base Sepolia key holding test USDC (see [Fund a test wallet](/docs/quickstart/skill#fund-a-test-wallet)). Without it, `akashi_discover` and `akashi_inspect` still work; `akashi_run` returns an error and signs nothing.

### 3. The tools

| Tool | Cost | Input | Returns |
| --- | --- | --- | --- |
| `akashi_discover` | free | `query` (at least 2 characters), `limit` (1–25, default 5) | Ranked candidates with id, price, health and hints |
| `akashi_inspect` | free | `id`, e.g. `firecrawl/search` | Description, input JSON Schema, output schema, price and an example |
| `akashi_run` | the tool's price | `id`, `input` (an object) | `status`, `body` (the result envelope), `receipt`, `ms` and `sessionSpentAtomic` |

A tool result longer than 12,000 characters is cut, and ends with `…[truncated]`.

## Spend caps

Two environment variables bound what the server may sign. Both are in USDC atomic units (6 decimals, so 1,000,000 is $1).

| Variable | Default | Meaning |
| --- | --- | --- |
| `AKASHI_MAX_ATOMIC_PER_CALL` | `10000` ($0.01) | Never sign a run priced above this. The catalog's highest price is $0.01. |
| `AKASHI_MAX_TOTAL_ATOMIC` | `100000` ($0.10) | Never sign more than this in one MCP session. |

When a cap would be passed, the run fails with a message that ends in "nothing was signed". A run that fails upstream is never charged, but a signed payment still counts toward the session total.

Set them next to the key:

```json
"env": {
  "AKASHI_PRIVATE_KEY": "0x…",
  "AKASHI_MAX_ATOMIC_PER_CALL": "5000",
  "AKASHI_MAX_TOTAL_ATOMIC": "50000"
}
```

`AKASHI_API_URL` points the server at another gateway (default `https://api.useakashi.xyz`).

## Try it

Ask your agent: "Use Akashi to find the latest release of astral-sh/uv." It should call `akashi_discover`, then `akashi_inspect` on `github/latest-release`, then `akashi_run` with `{"repo": "astral-sh/uv"}` ($0.001).
