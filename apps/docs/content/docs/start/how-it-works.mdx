This page explains the moving parts: how a paid request reaches Akashi through Pocket Network, how each service
turns it into evidence, and why the answer is shaped the way it is. For the exact fields, see
[the response contract](/docs/contract/response).

## The request path

1. **The agent asks the portal.** Every Pocket service is reached through the Agentic Portal at
   `https://agent.pocket.network/v1/<service-id>/<path>` (the test portal is `test.agent.pocket.network`). A request
   without payment gets `402 Payment Required` with the price: $0.005, payable in USDC on Base with x402 or on
   Tempo with MPP.
2. **The agent pays.** Its wallet signs an authorization for exactly that amount and sends the request again. No
   account, no API key.
3. **Pocket Network relays it.** The portal hands the request to a Pocket gateway, which sends it as a *relay* to a
   supplier staked for that service ID. Akashi's relay miner receives it and forwards it to the Akashi API.
4. **Akashi answers.** The API routes it to one of three services: `/cite`, `/code` or `/now`.
5. **The portal checks and returns.** It checks the answer against the service's published output schema and
   returns `{ "portal": { "provenance", "serviceId", "schemaCheck" }, "data": <Akashi's answer> }`.
6. **The work is settled on-chain.** The relay miner records its relays and submits claims and proofs to Pocket
   Network, which rewards the supplier according to the service's compute units per relay (citation-verify
   40,000, code-reality-check 20,000, live-facts 10,000).

<Callout title="What is live today">
The three service IDs are registered on Pocket Network Beta, and the Akashi API is running. The relay miner, the
supplier stake and the portal listing follow once Akashi's domain is in place, so paid calls through the portal are
not available yet. The API reference playground calls the API directly, free of charge.
</Callout>

## Inside Akashi

Every request gets a **hard stop**: 8.5 s for Citation Verifier, 7 s for Code Reality Check and 4 s for Live
Facts. Within it, a service asks all of its sources at once, each with its own concurrency and rate limits, and
caches what it learns so repeat questions are fast.

When the deadline arrives, whatever has not answered is named in `unavailable` and the answer is marked `partial`.
An item that depended on the missing source says so (`unverifiable` or `unknown`, `retryable: true`) instead of
guessing. An upstream outage is never a server error.

| 符 Code Reality Check | npm, PyPI, crates.io, Go, Maven, RubyGems, Packagist, NuGet, deps.dev, docs.rs | existence, then placeholder, typosquat and newness checks; a TypeScript compiler reads real type definitions for npm symbols |

Two indexes are rebuilt on a schedule rather than fetched live: news headlines from GDELT every 15 minutes and job
postings from public company job boards every 6 hours.

## Why answers look like evidence

An agent needs to act on the answer, and a person needs to be able to check it. So every result carries:

- **a typed verdict** from a fixed vocabulary, so code can branch on it (`not_found` is not a string to parse);
- **the records it was checked against**, with links, so anyone can confirm it;
- **how old the data is** (`as_of`, `freshness`) and **whether independent sources agree** (`agreement`);
- **what could not be checked**, instead of a confident guess.
