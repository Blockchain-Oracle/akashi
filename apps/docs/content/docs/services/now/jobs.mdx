---
title: Search job postings
description: Search open roles at 89 companies from an index of their public Greenhouse, Lever and Ashby job boards, filtered by words, company, location, remote, salary and posting date.
---

You will call `/v1/jobs` and read postings with their source board and posting date. You need a way to call Akashi
(the [mppx CLI](/docs/calling/curl-and-mppx) is the quickest; see [Calling Akashi](/docs/calling)).

## When to use it

- **"Who is hiring for X?"** among the indexed companies, with links straight to each posting.
- **Filtering by salary or remote work** where the posting states it.

The index covers 89 companies whose public boards Akashi checked one by one (61 on Greenhouse, 24 on Ashby, 4 on
Lever); it is not a search of the whole job market.

## Request

All fields are optional; with none, you get the newest postings.

<TypeTable
  type={{
    query: { type: "string", description: "Words that must all appear in the title or team; up to 200 characters." },
    companies: { type: "string[]", description: "Up to 20 company names; a posting matches any of them." },
    location: { type: "string", description: "Words that must appear in the location, e.g. Berlin." },
    remote: { type: "boolean", description: "true: remote postings only; false: postings not marked remote." },
    salary_min: { type: "integer", description: "Only postings that state a salary at or above this amount." },
    currency: { type: "string", description: "ISO 4217 code the stated salary must be in, e.g. USD." },
    posted_within_days: { type: "integer", description: "1 to 90 days.", default: "90" },
    limit: { type: "integer", description: "1 to 50 postings.", default: "10" },
  }}
/>

## Send it

```json title="Request body"
{ "query": "engineer", "remote": true, "limit": 3 }
```

```bash title="Terminal"
MPPX_PRIVATE_KEY=0x... npx -y mppx@0.11.0 https://test.agent.pocket.network/v1/live-facts/v1/jobs -J '{"query":"engineer","remote":true,"limit":3}' --protocol x402
```

  `live-facts` is listed. The answer on this page is real, captured from the running service.
</Callout>

## Reading the answer

- **`summary`** counts postings per job-board system (`ats`): here all three came from Ashby boards.
- **`salary`** is the posting's own text; **`salary_min`** and **`currency`** are parsed from it, so
  "$170K – $255.5K" becomes 170000 USD. When a posting states no salary, all three are `null`.
- **`posted_at`** is the date the board gives for the posting; **`url`** opens it on the company's board.
- **`provenance.as_of`** is when the index was last refreshed, and `freshness` turns `stale` when that was more than
  12 hours ago (two missed refreshes).
- The envelope's **`notes`** say that salary filters only match postings that state a salary; Greenhouse boards
  rarely do.

## Edge cases

<Accordions>
  <Accordion title="Why an index, not a live search">
    Each board is fetched every 6 hours by a scheduled task and written to a local full-text index; a request never
    waits on 89 job boards. That is why the answer takes tens of milliseconds.
  </Accordion>
  <Accordion title="Salaries in other currencies">
    Currencies are read from the salary text: "CA$215K" is Canadian dollars, not US dollars. Filter with `currency`
    to compare like with like.
  </Accordion>
  <Accordion title="The index is empty or old">
    If the index cannot be read, the envelope is `partial` with `ats-boards` in `unavailable` and a note. If it is
    more than 12 hours old, a note says how old.
  </Accordion>
</Accordions>
