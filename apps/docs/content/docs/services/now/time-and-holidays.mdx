Time zones come from the IANA tz database (release `2026d`); a note appears when IANA has published a newer one.
Holidays are compared across python-holidays, Nager.Date and OpenHolidays.

## Example

```json title="{ place: New York, at: 2026-10-20T12:00:00Z, convert_to: [America/Edmonton, Asia/Tokyo] } · results[0] (trimmed)"
{
  "kind": "time",
  "zone": "America/New_York",
  "matched": "zone city New York",
  "local_time": "2026-10-20T08:00:00-04:00",
  "utc_offset": "-04:00",
  "abbreviation": "EDT",
  "is_dst": true,
  "next_transition": { "at": "2026-11-01T06:00:00+00:00", "offset_before": "-04:00", "offset_after": "-05:00" },
  "conversions": [
    { "zone": "America/Edmonton", "local_time": "2026-10-20T06:00:00-06:00", "abbreviation": "MDT" },
    { "zone": "Asia/Tokyo", "local_time": "2026-10-20T21:00:00+09:00", "abbreviation": "JST" }
  ],
  "tzdb_version": "2026d",
  "tzdb_latest": "2026d",
  "provenance": { "sources": ["tzdb"], "freshness": "fresh", "agreement": "single_source", "licence": "public domain" }
}
```

## Reading it

- `matched` says how a place resolved.
- `next_transition` is when the offset changes next; `null` means not within two years.
- Holidays listed by every source are `agree`; a date one source omits is `minor_diff`.
- NYSE is not the federal calendar: Good Friday is an NYSE holiday, Columbus Day is not.
- Three NYSE business days after 2026-11-25 is 2026-12-01; Thanksgiving is skipped.
