This page explains the idea behind `live-facts` and how to read the provenance on every answer. To make a call, go
straight to one of the [guides](#guides).

## The problem: facts that change

A language model's knowledge stops at its training cut-off, and it cannot tell which of its facts have since
changed. Some change on a schedule, some without warning:

- **Time-zone rules change.** Governments move their clocks with little notice. The IANA tz database ships several
  releases a year; `live-facts` runs on a pinned release (`2026d`) and says so when a newer one exists.
- **Rates are fixed daily, and not all at the same hour.** The ECB publishes after 16:00 Frankfurt time; the Bank of
  England and the Bank of Canada trail it by a day intraday; the Federal Reserve's H.10 series is weekly.
- **Calendars disagree.** A US federal holiday is not an NYSE holiday, and in 2026 one holiday dataset lists only
  the observed Friday of Independence Day (July 3) while another lists both the Friday and the Saturday.
- **Office holders change.** A model trained a year ago may name the wrong prime minister with full confidence.

An agent that answers these from memory is fluent and wrong. `live-facts` answers them from the sources, and shows
its working.

## Provenance: the working, on every result

Every result has a `provenance` object. It is the part an agent should repeat alongside the value.

<TypeTable
  type={{
    sources: { type: "string[]", description: "The sources the value was taken from, e.g. ECB, BOC, met.no, nws." },
    as_of: { type: "string | null", description: "When the underlying data was true or published: a fixing date, a forecast's issue time, a tzdb release." },
    age_seconds: { type: "number | null", description: "Seconds between as_of and the answer, when as_of is a point in time." },
    freshness: { type: '"fresh" | "lagging" | "stale" | "unknown"', description: "Measured against the source's own publishing schedule (see below)." },
    agreement: { type: '"agree" | "minor_diff" | "conflict" | "single_source"', description: "Whether independent sources give the same answer." },
    spread_pct: { type: "number | null", description: "For numeric values: (max − min) ÷ median of the compared values, in percent." },
    licence: { type: "string | null", description: "The terms the data comes with, e.g. CC0, CC BY 4.0, central-bank reference data." },
    attribution: { type: "string | null", description: "How the source asks to be credited." },
  }}
/>

### Freshness is judged by each source's own schedule

A value is not "old" in the abstract; it is old for its source. `fresh` means the newest data the source publishes,
`lagging` means on the source's own schedule but behind the others, `stale` means later than the source's schedule
allows, and `unknown` means the schedule could not be checked.

| Fact | What "fresh" is measured against |
|---|---|
| Time | the newest tzdb release IANA has published (checked daily); pinned rules behind it are `stale` |
| Exchange rates | each central bank's cadence: a daily fixing is `stale` after 2 business days, a weekly one (FRED H.10) after 6; an older fixing than the newest is `lagging` |
| Weather | the forecast in force: `as_of` is its issue time, and MET Norway's `Expires` header decides when it is fetched again |
| News | the GDELT index, refreshed every 15 minutes; a note appears when it is more than 30 minutes old |
| Jobs | the job-board index, refreshed every 6 hours; `stale` after 12 hours |
| Stock quotes | the NYSE session: a quote from before the last completed session is `stale` |

### Agreement is tested per kind of fact

Disagreement is reported, never averaged away:

| Fact | Compared on | `agree` | `minor_diff` | otherwise |
|---|---|---|---|---|
| Exchange rates | spread of the current fixings | ≤ 0.5 % | ≤ 1.5 % | `conflict` |
| Weather | temperature gap in °C (percentages are meaningless near 0 °C) | ≤ 1.5 °C | ≤ 3.0 °C | `conflict` |
| Holidays | the set of dates each source lists | identical | up to 3 dates differ (or 20 % of them, if more) | `conflict` |
| Stock closes | one session's official close from two feeds | ≤ 0.1 % | ≤ 1 % | `conflict` |

Time, Wikidata facts, news and jobs each have one authoritative source, so they are `single_source`.

## A worked example: a conflict, reported

Here is a real answer for US dollars to Nigerian naira. Four central banks publish the pair; one of them is not like
the others.

```json title="POST /v1/fx · results[0] (trimmed to the result)"
{
  "kind": "fx_rate",
  "base": "USD",
  "quote": "NGN",
  "rate": 1329.9737,
  "date": "2026-09-30",
  "amount": null,
  "converted": null,
  "providers": [
    {
      "provider": "BOTA",
      "name": "Bank of Tanzania",
      "rate": 1332.49,
      "date": "2026-09-30",
      "rate_type": "indicative rate",
      "issuer": false,
      "cadence": "daily",
      "freshness": "fresh",
      "business_days_old": 0
    },
    {
      "provider": "CBG",
      "name": "Central Bank of The Gambia",
      "rate": 1205.5,
      "date": "2026-09-29",
      "rate_type": "indicative rate",
      "issuer": false,
      "cadence": "daily",
      "freshness": "lagging",
      "business_days_old": 1
    },
    {
      "provider": "BNA",
      "name": "Banco Nacional de Angola",
      "rate": 1329.01,
      "date": "2026-09-29",
      "rate_type": "reference rate",
      "issuer": false,
      "cadence": "daily",
      "freshness": "lagging",
      "business_days_old": 1
    },
    {
      "provider": "CBN",
      "name": "Central Bank of Nigeria",
      "rate": 1329.9737,
      "date": "2026-09-29",
      "rate_type": "official exchange rate",
      "issuer": true,
      "cadence": "daily",
      "freshness": "lagging",
      "business_days_old": 1
    }
  ],
  "provenance": {
    "sources": [
      "BOTA",
      "CBG",
      "BNA",
      "CBN"
    ],
    "as_of": "2026-09-30",
    "age_seconds": 33441,
    "freshness": "fresh",
    "agreement": "conflict",
    "spread_pct": 9.5518,
    "licence": "central-bank reference data",
    "attribution": "Central-bank reference rates via Frankfurter (frankfurter.dev)"
  }
}
```

Read it top to bottom:

1. **`rate` is 1329.9737**, the Central Bank of Nigeria's own fixing. When the quote currency's issuer publishes a
   current rate (`issuer: true`), that is the headline; otherwise it is the median of the current fixings.
2. **`providers`** lists every fixing with its date and its age in business days. The Central Bank of The Gambia
   says 1205.5, about 9 % below the other three.
3. **`agreement` is `conflict`** and **`spread_pct` is 9.55**: the answer does not hide the outlier, and an agent can
   say "the official rate is 1,329.97; one central bank publishes a rate about 9 % lower".
4. **`freshness` is `fresh`**: the newest fixing is from today (2026-09-30), and the others are within one business
   day of it.

## The four-second budget

`live-facts` has a hard stop of **4 seconds**. Sources are asked in parallel; one that has not answered by then is
listed in the envelope's `unavailable` array, the envelope's `status` becomes `partial`, and the result is built from
the sources that did answer. An upstream outage is never a server error. See
[the response contract](/docs/contract/response).
