---
title: Check packages before you install them
description: Ask whether a package is real, a typosquat, a placeholder or brand new, and which versions exist, before running npm install or pip install.
---

You will check packages the way an installer should: is the name published, is it the package you think it is,
and does the version exist? You need a way to call Akashi (see [Call Akashi](/docs/calling)).

## When to use it

Before installing a dependency that a model suggested, or when reviewing a requirements file or `package.json`.
`/v1/package` checks one, `/v1/packages` up to 100, and `/v1/versions` lists versions and resolves a range.

## Send it

```bash title="Check one npm package"
MPPX_PRIVATE_KEY=0x... npx -y mppx@0.11.0 https://test.agent.pocket.network/v1/code-reality-check/v1/package -J '{"ecosystem": "npm", "name": "left-padx"}' --protocol x402
```

<Callout type="warn" title="Not on the portal yet">

## Reading the answer

- **`verdict`** and **`exists`** (`yes`, `no` or `unknown`) answer the main question.
- **`typo_of`** names the popular package the name is close to, with the edit `distance`, the `method` that found
  it and the target's popularity rank. **`did_you_mean`** lists real names to use instead.
- **`evidence`** says, in words, what the verdict rests on. **`risk_signals`** gives the same as codes, such as
  `not_on_registry`, `typo_of_popular`, `placeholder`, `new_low_signal` or `version_not_found`.
- For a package that exists: **`latest`**, **`version_exists`**, **`first_published`**, **`latest_published`**,
  **`versions_count`**, **`downloads_last_week`**, **`popularity_rank`** and the last ten versions in
  **`versions_tail`**.
- **`see_also`** points to Pocket's `package-advisories` and `taint-check` services for known vulnerabilities, which
  this service does not check.

### How each verdict is decided

| Verdict | Rule |
|---|---|
| `does_not_exist` | The registry has no such package |
| `placeholder` | npm's `0.0.1-security` holding version, a description saying "placeholder", "security holding package", "reserved", "do not use" and similar, or an npm package under 1 KB with at most two files and no entry point |
| `likely_typo` | Within two edits (one for names of five characters or fewer) of a package at least 100× more popular, and, on npm, with fewer than 1,000 downloads last week; elsewhere, also suspiciously new |
| `suspicious_new` | First published less than 90 days ago, with fewer than 1,000 downloads last week or at most two versions |
| `yanked` · `deprecated` | The version is yanked, or the package is deprecated, with the maintainer's reason |
| `ok` | None of the above |
| `unknown` | The registry did not answer in time; `retryable: true` |

## Edge cases

<Accordions type="single">
  <Accordion title="The version does not exist">
    A package that exists but lacks the version you asked for keeps its verdict; `version_exists` is `no`,
    `risk_signals` gains `version_not_found`, and `evidence` names the latest version.
  </Accordion>
  <Accordion title="A missing name can appear any minute">
    Answers for packages that do not exist are cached for only five minutes, because a squatter may register the
    name at any time. Check again right before installing.
  </Accordion>
  <Accordion title="The registry did not answer">
    The verdict is `unknown` with `retryable: true`, and the registry is named in the envelope's `unavailable` list.
  </Accordion>
  <Accordion title="Vulnerabilities">
    A package can be real, popular and vulnerable. This service does not check advisories; `see_also` points to the
    Pocket services that do.
  </Accordion>
</Accordions>
