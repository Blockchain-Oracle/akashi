---
title: Check a code snippet
description: Send a snippet to /v1/check and get one diagnostic, with its line and column, for every import and call it makes.
---

You will check a snippet the way a linter would, except that every reference is checked against the real
registries. You need a way to call Akashi (see [Call Akashi](/docs/calling)).

## When to use it

Before running or suggesting code a model wrote. One call covers every import and every call on an imported
module, so it is the quickest way to catch an invented package or method.

## What gets checked

The snippet is parsed (tree-sitter), and each reference is mapped to a package:

- **Imports**, including aliases (`import numpy as np`, `from x import y`, `import x from "x"`, `require("x")`).
- **Calls and attribute access** on an imported name (`requests.get`, `axios.fetchJson`), with one level of
  instance inference: after `s = requests.Session()`, `s.mount` is checked as `requests.Session.mount`.
- **Standard libraries are skipped**: Python's standard library, Node built-ins and `node:` imports, Go paths
  without a dot, and Rust's `std`, `core` and `alloc`.
- **Python import names are mapped to packages**: `PIL` to `pillow`, `cv2` to `opencv-python`, `sklearn` to
  `scikit-learn`, `yaml` to `PyYAML`, `bs4` to `beautifulsoup4`, and others.

At most 60 references are checked per snippet.

## Send it

```bash title="Check a TypeScript snippet with axios pinned to 1.7.9"
MPPX_PRIVATE_KEY=0x... npx -y mppx@0.11.0 https://test.agent.pocket.network/v1/code-reality-check/v1/check -J '{"language": "typescript", "code": "import axios from \"axios\";\n\nconst data = await axios.fetchJson(\"/api\");\n", "versions": {"axios": "1.7.9"}}' --protocol x402
```

<Callout type="warn" title="Not on the portal yet">
  Akashi's services are registered on Pocket Network (Beta) but not yet listed on the agent portal, so this call works
  once they are listed. The answers on this page were captured from the running service.
</Callout>

The command pays with a Base Sepolia wallet through x402. To set up a client in code, see [Call Akashi](/docs/calling).

## Reading the answer

Each result is a diagnostic for one reference, in source order:

- **`line`, `column`, `end_line`, `end_column`** locate it (lines from 1, columns from 0), and **`text`** is what
  was checked, such as `axios.fetchJson`.
- **`ref_kind`** is `import`, `call` or `attribute`.
- **`package`**, **`version`** and **`target`** name the package, the version checked and the symbol looked up.
- **`verdict`** is one of `ok`, `nonexistent_package`, `placeholder`, `likely_typo`, `suspicious_new`,
  `nonexistent_symbol`, `deprecated` (also used for yanked versions) or `unknown`.
- **`fix_hint`**, **`did_you_mean`**, **`signature`** and **`reason`** help you fix it: the likely intended package,
  close real names, the real signature, and the evidence behind a package verdict.

Here the import is fine, but `axios.fetchJson` does not exist in axios 1.7.9's type declarations.

## Edge cases

<Accordions type="single">
  <Accordion title="A missing package marks every line that uses it">
    Package problems win: if a package does not exist, is a placeholder or is a likely typo, every reference to it
    gets that verdict, because it is the root cause. Symbols are only looked up in packages that exist.
  </Accordion>
  <Accordion title="unknown is not 'does not exist'">
    `unknown` means the registry or the type information could not be read in time. Retry before concluding
    anything.
  </Accordion>
  <Accordion title="Pin the versions you will install">
    Methods come and go between versions. Without a pin the latest version is checked, which may differ from the
    one in a lockfile. Pass `versions` to check the ones you use.
  </Accordion>
  <Accordion title="Long snippets">
    Only the first 60 references are checked. Split large files, or check the packages with
    [`/v1/packages`](/docs/services/code/packages-and-typosquats).
  </Accordion>
</Accordions>
