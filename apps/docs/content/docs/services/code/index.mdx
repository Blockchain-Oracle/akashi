---
title: Code Reality Check
description: Do the packages, versions and functions in a snippet exist before anyone installs them? Capability ID code-reality-check.
---

Every import and call is checked against the registry it comes from and the package's published type information.
Invented packages, placeholders and near-miss typos are flagged before an install.

<ServicePipeline service="code" />

## Verdicts

<VerdictGrid set="package" />

In a snippet, a missing package shows as `nonexistent_package` and a missing function as `nonexistent_symbol`.

## Endpoints

| Endpoint | Answers |
|---|---|
| [`POST /v1/check`](/docs/reference/code/check) | every import and call in a snippet, with line and column |
| [`POST /v1/package`](/docs/reference/code/package) · [`/v1/packages`](/docs/reference/code/packages) | one package, or up to 100 |
| [`POST /v1/versions`](/docs/reference/code/versions) | the versions of a package, and which one a range resolves to |
| [`POST /v1/symbol`](/docs/reference/code/symbol) · [`/v1/symbols`](/docs/reference/code/symbols) | does a function or class exist, and its signature |

Registries: npm, PyPI, crates.io, Go, Maven, RubyGems, Packagist and NuGet.
