## Endpoints

| Endpoint | Checks |
|---|---|
| `POST /v1/check` | a whole snippet (Python, TypeScript, JavaScript, Go or Rust): every import and call |
| `POST /v1/package`, `/v1/packages` | one or up to 20 packages |
| `POST /v1/versions` | whether a version or range exists |
| `POST /v1/symbol`, `/v1/symbols` | whether a function, class or method exists in a package version |

Registries: npm, PyPI, crates.io, Go, Maven, RubyGems, Packagist and NuGet.

## Package verdicts

When several apply, the first in this list wins.

| Verdict | Meaning |
|---|---|
| `does_not_exist` | no such package in the registry |
| `placeholder` | it exists but holds nothing: a security placeholder or reserved name; `evidence` says why |
| `likely_typo` | it is a near-miss of a popular package (`requestz` for `requests`); the intended name is suggested |
| `suspicious_new` | published recently, with almost no downloads |
| `yanked`, `deprecated` | withdrawn or marked deprecated by its maintainer, with the reason |
| `ok` | exists and none of the above applies |
| `unknown` | the registry could not be asked in time |

## Snippet diagnostics

`/v1/check` returns one diagnostic per reference, pointing at its line: `ok`, `nonexistent_package`, `placeholder`,
`likely_typo`, `suspicious_new`, `nonexistent_symbol` (with the closest real names and their signatures),
`deprecated` or `unknown`.

`unknown` never means "does not exist": it means the answer could not be established in time.
